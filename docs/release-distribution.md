# v0.1 Distribution Decision

JobLens v0.1.0 will ship through **GitHub Releases with an installable npm-format tarball attached to the release**.

Publishing the package to the public npm registry is deferred until after v0.1.0. npm account/package-name ownership is an external distribution concern and is not required to validate the local-first product boundary.

The release gate therefore verifies the exact tarball produced by `npm pack`:

1. build the package from the release commit;
2. generate the `.tgz` with the package allowlist;
3. install that tarball into a clean temporary npm project;
4. run the installed `joblens --help` binary;
5. run installed `joblens setup` against the public synthetic candidate template and a fresh private workspace;
6. start the installed `joblens-mcp` binary through an MCP client, complete stdio initialization, list tools, and read the persisted profile.

The stable GitHub Release should attach the same `.tgz` artifact that passed the release gate, together with source archives generated by GitHub.

A later release may additionally publish to npm after registry ownership and release automation are configured. Adding npm distribution does not change the JobLens domain or workflow contracts.
